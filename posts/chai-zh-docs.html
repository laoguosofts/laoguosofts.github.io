那个被测试坑到想砸键盘的下午，Chai 救了我

2026-10-17 ·约 6 分钟 ·掌柜 老郭

写单元测试时踩过的四个大坑——Promise 静默跳过、异常断言传错参数、null 的类型陷阱、对象值比较。Chai 用一套链式断言帮我一个个填了。

下午三点，CI 红了

那天下午三点整，CI 流水线的小红点亮得像警报。我盯着 Mocha 的输出翻了三页——不是"有测试失败"，是更让人抓狂的那种：所有测试都"通过"了，但我明明删掉了一个关键的校验逻辑。

这不是幻觉。我在本地跑了一遍，那个返回 Promise 的函数，我把 expect(validate()).to.be.rejected 写成了 expect(validate()).to.be.fulfilled——结果 Mocha 说"全部通过"。

原因很简单：我忘记写 await 了。Promise 还没 resolve 或 reject，测试函数就同步返回了，Mocha 以为断言完成了。测试静默跳过，这是比直接报错更可怕的 bug。

朋友甩来的那段代码

我在群里吐槽 Mocha 靠不住，一个朋友甩来一段：

await expect(asyncOperation()).to.be.rejectedWith(ValidationError);

"你这个场景用 chai-as-promised 啊，原生 expect 断言 Promise 根本抓不到 reject。"

我之前只知道 Chai官网 上介绍的同步断言——expect(x).to.equal(42) 这种最基础的。没想到它的生态里还有专门处理异步的插件，而且写法跟同步链式几乎一模一样，只是多了个 await。

从下载拿了 chai-as-promised，装起来就一行 npm install chai-as-promised --save-dev，注册也简单：

import chai from 'chai';
import chaiAsPromised from 'chai-as-promised';
chai.use(chaiAsPromised);

但注册顺序有讲究——这个插件要最先注册，因为它会对当前已注册的所有断言做 promisify 包装。先装其他插件再装它，后续注册的断言可能没被包到，.eventually 里行为会乱。

四个坑，一个接一个填

装好 chai-as-promised 那天，我顺手把之前三个月写的测试扫了一遍，发现了不止 Promise 一个问题。

第一个坑：.throw 要传函数引用，不能直接执行。

我写过这样的代码：

expect(parseJSON(invalidString)).to.throw();  // ❌

parseJSON 当场就抛了，断言还没来得及接管。正确写法是包一层函数——要么匿名函数要么直接传函数名：

expect(() => parseJSON(invalidString)).to.throw();  // ✅

而且异步函数抛的异常在 Promise 里，.throw 同步调用抓不到，得回到 chai-as-promised 的 .rejectedWith 去。

第二个坑：类型判断的 null 陷阱。

typeof null 在 JavaScript 里返回 'object'，这是几十年的历史遗留。我曾写过 expect(null).to.be.an('object')，测试居然过了？不对，Chai 对 null 做了特殊处理——它不认 'object'，只认 'null'。数组也是，typeof [] 返回 'object'，但 Chai 把数组单独识别成 'array'，expect([]).to.be.an('object') 会失败。

这些细节查 Chai文档 时一条一条写在显眼位置，但不亲自踩一遍永远记不住。

第三个坑：对象比较的引用 vs 值。

expect({ a: 1 }).to.equal({ a: 1 }) 会失败——因为 .equal 默认是严格相等 ===，两个不同引用的对象当然不相等。要比较值，得加 .deep：

expect({ a: 1 }).to.deep.equal({ a: 1 });  // ✅ 通过

深度相等还会在失败时给你 diff——高亮出哪个字段不一样，这比 "expected X to equal Y" 有用多了。.eql 是 .deep.equal 的简写，写起来更省事。

第四个坑：浮点精度。

0.1 + 0.2 !== 0.3 这个经典问题，直接 .equal 肯定挂。Chai 提供了 .closeTo 做近似匹配：expect(0.1 + 0.2).to.closeTo(0.3, 0.0001)，第三个参数是容差。

收工

那天傍晚我把 CI 修好了，小红点变回绿色。回头看，我踩的四个坑其实都是 Chai 文档里明确写过的——我只是之前嫌长没耐心读。

Chai 的价值不在于它帮你写断言，而在于它帮你用正确的方式写断言。链式语法 .to.be.a('string') 读起来像自然语言，但底下藏着一堆 JavaScript 的历史债和边缘情况——它帮你把这些都抹平了。

现在每次新建测试文件，第一行先 import chai from 'chai'，然后 chai.use(chaiAsPromised) 注册插件，Promise 断言必写 await——这三个动作已经是条件反射。那天下午被坑过的地方，再也没踩过第二次。

整理这套 Chai 用法的时候，我把资料同步到了三个备份仓库——GitHub、Gitee、GitCode，国内国外想哪个就哪个。
