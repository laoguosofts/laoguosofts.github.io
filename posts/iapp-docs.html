iApp 十年版本进化史：从安卓开发工具到跨平台全栈引擎

2026-10-17 ·约 7 分钟 ·掌柜 老郭

从裕v3到裕v7，iApp 走过了一条奇特的进化路线——既要照顾老用户生态，又要咬牙推进语法现代化，跨平台打包能力到底是怎么拼出来的？

开场：现在这版 iApp 是什么样

我最近从官方下载拿了安装包重新装了一次 iApp，打开新建项目向导时，盯着语言版本那五个单选框愣了一下——裕v7、裕v6、裕v5、游戏、裕v3，整整齐齐排着队。官方教程明确写着"没有特殊理由选裕v7"，但社区里翻一翻，v3 的老项目源码、视频教程、现成案例，比 v7 多得多。这就是 iApp 现在最有意思的地方：两套生态并行，一个在往前跑，一个在往后沉。

最新的裕v7 是它的拳头：语法终于有了 if、for、类模块这些像模像样的现代结构，不再是 v3 那种用 s 赋值、f 判断、syso 输出的怪风格。更关键的是 v7 是唯一能跨平台打包的版本——电脑 exe、苹果 ipa、网页 html、鸿蒙应用，一套代码多端跑。而 v3 呢，生态最厚，网上能搜到的教程、源码、社区讨论十有八九是 v3 的，但它打不了 exe，也出不了 html。

来路：它从哪起步

样本文档里没提更早的版本历史，但从 v3、v5、v6、v7 这一串编号能拼出一条线——iApp 不是从零开始设计好跨平台的，它是一边做一边改出来的。

v3 是那个"能读懂社区老代码"的版本，也是生态厚度的根基。文档里提到"官方更新日志近年把重点放在 v3 修复与 v7 新增功能上"，这句话有意思——v3 没被废弃，而是转到了维护模式。v5 和 v6 是过渡版本，"主要服务于老项目维护"，新项目没有主动选它们的理由。这说明 v7 不是凭空冒出来的，中间有至少两代在铺路。

我自己用过 v3，那种语法确实反直觉：变量赋值用 s，条件判断用 f，输出用 syso。写惯了主流语言的人看 v3 代码会觉得像某种私货。但 v3 的优点也很实在——它够老，够简单，网上教你做一个记账本 App 的视频，从零到能跑全在 v3 里完成，连换版本的机会都不给你。

关键转折点：裕v7 为什么是分水岭

v7 的变化不是增量优化，是范式切换。文档样本里有一句很关键的话："语法现代（if、for、四类变量、类模块）"——这几个字背后是整个语言体系的重写。v3 没有真正的 if 语句，v5/v6 可能在往这边靠，但没走到底，v7 直接把现代控制结构放进来了。

更重要的是跨平台打包。iApp 之前的定位就是"安卓开发工具"，做出来的东西只能是 APK。v7 突然说一套代码能出 exe、ipa、html、鸿蒙包——这不是加了几个导出格式，是把产品定位从"安卓开发工具"拉到了"跨平台引擎"。你看现在iapp官网上的介绍，不再只提"可视化设计界面，让你设计应用界面一目了然"，而是把打包能力和语法一起摆出来讲。

可视化布局这个招牌能力一直没变——从 v3 到 v7，组件面板、设计画布、属性设置三块区域的基本节奏没动过，"添加控件 → 设置大小 → 摆位置 → 挂事件"这套四步口诀在文档里反复出现。变的是画完之后能去哪：以前只能变成 APK，现在能变成四种东西。

迭代规律：团队一直在死磕什么

从现有版本的功能分布和官方更新的侧重点，能看出 iApp 团队的优先级逻辑：

死磕语法现代化。v5 到 v6 到 v7 是一条清晰的演进线，每一代都在往"更像主流语言"靠，直到 v7 才把类模块、四类变量这些基石搭好。文档里说"v5/v6 是过渡版本"，但过渡了两代才走到 v7——说明语法重写这件事比做界面难多了。

死磕跨平台，但只在新版上做。v3 生态那么厚，但跨平台能力一块都不给它。v7 独占所有打包格式，本质上是团队在说：v7 才是未来，v3 是存量用户的安全网。官方更新日志"v3 修复 + v7 新增"的分配，就是这个逻辑。

旧语法不删，只做兼容。v5/v6 没有被废弃，v3 也还能建新项目——团队不想做那种强制迁移、得罪老用户的事。裕语言五个选项摆在那，用户爱选哪个选哪个，只是新版功能只给最新版。

预判：下一步大概会怎么走

这些是从迭代规律推的，不是官方口径：

第一，v7 语法会继续深挖，但不太会再出 v8 了。 因为 v7 才刚把类模块、四类变量这些基础补全，接下来应该是在 v7 上做库扩展和体验打磨，而不是又开一代语法。跨平台打包的覆盖率倒是可能继续扩——现在有 exe/ipa/html/鸿蒙，下一个是谁？

第二，v3 的维护窗口会收窄，但不会立刻死。 官方现在还在修 v3，是因为社区老项目太多了。但如果 v7 的生态厚度能赶上 v3（现在差得远），v3 就会真的进入纯归档状态——不再修 bug，只保留能打开的能力。

第三，可视化设计这条线会一直是招牌。 从样本文档的篇幅分配就能看出来，拖拽布局、属性设置、事件挂接这部分占了很大比重，是 iApp 区别于 Flutter、UniApp 这些框架的核心差异点。别人是"写代码生成界面"，iApp 是"画界面挂事件"——这个定位不会丢。

写在最后

我特意去 iapp文档翻了一下才弄明白，样本文档没写的早期版本历史不是疏忽，是 iApp 这个产品本身就不太爱宣传自己——"重庆联思创信息科技有限公司"这个开发者名字，在各大应用商店的介绍里都不显眼，社区讨论也大多集中在具体问题而非路线图。这种低调风格其实和版本策略是一致的：默默把 v7 堆出来，默默把 v3 维护好，用户你能看懂哪个就用哪个。

如果你是个新手，别纠结——直接建 v7 项目，跟着官方最新教程走就对了。v3 生态厚是事实，但那堆老代码读起来费劲，不如花半小时建个 v3 练手项目跑一遍基本指令，目的是"能读懂"社区老代码，不是真的去写。两套语法别混，一个项目从头到尾只用一套，这是过来人的建议。
