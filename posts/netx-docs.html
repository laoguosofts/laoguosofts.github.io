用 NetX 把家里局域网摸得门儿清——从零跑通设备扫描与远程唤醒

2026-10-17 ·约 8 分钟 ·掌柜 老郭

刚装完 NetX 就能把家里所有联网设备找出来？这篇实战教程带你从零跑通扫描、识别、WOL 唤醒全流程，避开新手最容易踩的三个坑。

这篇教程结束时，你能做到三件事：扫出家里局域网每一台联网设备、认出哪些是蹭网的陌生设备、用手机把电脑从关机状态远程点亮。全程只需要一个 Android 手机和一个从NetX官网拿的安装包。

准备工作

先说几个前置条件，省得你扫不出来还以为自己操作错了。

  • 平台：Android 手机（iOS 上功能受限，主要是 WiFi 扫描这一项拿不到系统级权限）
  • 系统版本：Android 9 以上都没问题，Android 13+ 会多一个通知权限弹窗
  • 手机和目标设备必须在同一个 WiFi——这是局域网扫描的基本前提
  • 安装包从官方下载拿就行，Google Play 或者国内的应用商店搜 NetX 都能找到

别急着打开应用先看权限弹窗，这里是新手翻车的高发区。

第一步：装完之后先别急着扫

打开 NetX，它会一口气弹好几个权限请求。你得心里有数哪个是核心哪个可以以后再说。

权限能不能拒绝拒绝后果
位置（精确）不能WiFi 扫描直接空白，一个设备都扫不到
位置（粗略）可以部分旧版 Android 上兜底用
通知（Android 13+）可以不推送新设备告警
存储可以（Android 10+）分区存储后基本用不上

这里提醒一下：点"始终允许"或"仅在使用时允许"都行，别点"拒绝"。尤其是位置权限——Android 从 10 开始把 WiFi 扫描和位置绑定了，没有位置权限的话系统根本不让应用发起 WiFi 扫描，这不是 NetX 的 bug，是 Android 的安全策略。

权限过了之后，你会看到主界面那个大大的扫描按钮。

第二步：跑第一次扫描，看看家里都有啥

点一下扫描按钮，等个三五秒。NetX 会同时用两种方式找设备：

  • ARP 扫描：遍历整个子网（比如 192.168.1.1~192.168.1.254），能响应 ARP 的设备都会被列出来
  • Bonjour / NetBIOS 广播监听：被动等设备自己报名字，这步慢一点，通常需要 10~15 秒

扫描结束后你会看到一排卡片，每张卡片代表一台联网设备。卡片上已经帮你填了 IP、MAC 地址、厂商、主机名。

扫完第一遍别着急往下走，先做件事：对着每台不认识的设备点进去看详情。

第三步：点开任意设备，详情页里藏着什么

进入设备详情页后，界面分三块，我带你逐块看。

顶部：基本信息卡

这一块是 NetX 扫描到的原始数据，包括 IP、MAC、厂商、主机名、连接方式。不同类型的设备展示的东西不一样：

  • Windows 电脑通常会显示 NetBIOS 名，比如 YANG-PC
  • Mac 会显示 Bonjour 名，末尾带 .local
  • iPhone 的厂商会显示 Apple，主机名可能是"张三的 iPhone"
  • 米家设备厂商是 Xiaomi，主机名常常是空的

主机名那一栏如果空着，不是 NetX 漏扫了，是那个设备没主动广播名字。别慌，往下看 MAC 厂商反查那一招。

中部：远程控制按钮

这里有三个按钮：唤醒、SSH 控制、远程监控（Pro 版）。唤醒就是 WOL，这个我们稍后细说。SSH 控制需要目标设备上开 SSH 服务端，远程监控看 CPU/内存也是 Pro 版的功能。

底部：诊断工具

Ping 测试、端口扫描、Traceroute、IP 地理定位，这四个是网络工程师常用的工具，NetX 直接塞进 App 里了。后面排查网络问题时会很有用。

第四步：用 MAC 反查，认出那些没名字的设备

有些设备主机名是空的，但厂商已经帮你查好了——NetX 在扫描阶段就自动把 MAC 前缀拿去匹配厂商数据库了。不过如果你想额外确认，详情页里 MAC 地址旁边有个查询按钮，点一下就弹出厂商信息。

这个数据库是预打包在应用里的，不需要联网，覆盖了常见的几千家厂商。实战中你可以这么快速判断陌生设备：

厂商大概率是什么
AppleiPhone / iPad / Mac
Xiaomi米家智能设备（音箱、扫地机、摄像头）
TP-Link / Tenda路由器
Realtek / Atheros杂牌网卡或老旧路由器
查不到厂商值得重点关注

扫完局域网后把厂商查不到的设备记下来，单独验证一下是不是自己家的。蹭网的设备通常就在这里暴露。对 MAC 反查还想深挖的话，NetX文档里有更完整的厂商数据库说明和手动查询方法。

第五步：WOL 远程唤醒——让手机把电脑点亮

这是 NetX 最实用也最容易翻车的功能。按 NetX 上的唤醒按钮，它会向目标设备的 MAC 地址发送一个"魔法包"，理论上电脑应该从关机状态直接亮起。但实际场景里十次有三次没反应，我们一步步排查。

先确认 MAC 地址对不对

这是最常见的失败原因。如果 NetX 里存的 MAC 和电脑实际 MAC 差一个字符，魔法包发出去就是石沉大海。确认方法：找一台正常开机的同局域网电脑，NetX 扫描时能扫到它，进详情页记下 MAC。或者直接去电脑上查：Windows 命令行执行 ipconfig /all，找"物理地址"那一行。

再看 Windows 电源管理

Mac 地址没错的话，进 Windows 设备管理器：

  1. 右键开始菜单 → 设备管理器
  2. 网络适配器 → 右键网卡 → 属性
  3. 电源管理 → 勾上允许此设备唤醒计算机
  4. 高级 → 找到 Wake on Magic Packet 或 Wake on LAN，启用它

最后查 BIOS

重启进 BIOS（F2 / Del / Esc 看主板型号），找 Power Management 或 Wake Up Event Setup，启用 Wake on LAN / Power On By PCI-E。保存退出。

关机后看网卡灯

电脑正常关机（不是休眠）之后，网线口的灯应该是亮的——说明网卡还在低功耗待机等着接魔法包。如果灯灭了，说明 Windows 或 BIOS 里没开 WOL，回去重查。

快速验证法：先在局域网内测一遍 WOL。局域网能唤醒、蜂窝网络不行，那问题 100% 在公网配置（端口转发 / DDNS / 公网 IP），不用瞎折腾电脑。

新手最容易踩的三个坑

坑一：扫不出设备 = 手机没给位置权限。前面说过的，Android 把 WiFi 扫描和位置绑定了，拒绝位置权限等于把扫描功能废掉。

坑二：WOL 唤醒不了 = MAC 地址记错了。别跳过第一步的 MAC 核对，这个真的是九成失败的根因。

坑三：以为 NetX 能扫到所有设备。蓝牙设备、手机热点下的设备、某些开启了 MAC 随机化的 iPhone——这些是扫不到的，不是 NetX 的问题。

进阶玩法一句话

等你把扫描和 WOL 用熟了，可以试试在路由器里配好端口转发，然后把手机切到蜂窝网络，从外面唤醒家里的电脑——出门前发现文件没拷，掏手机点一下就搞定。
