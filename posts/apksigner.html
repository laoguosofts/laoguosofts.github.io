Apksigner 新手入门：手机上给 APK 签名，五分钟跑通

2026-10-17 ·约 7 分钟 ·掌柜 老郭

第一次接触 APK 签名？不用担心，Apksigner 让这件事在手机上就能完成。跟着这篇走，从零到签出第一个自己的包，全程不碰电脑。

这篇能带你从零开始，在手机上给自己的 APK 包签名——不需要电脑，不需要懂什么是签名，跟着一步步点就行。

它到底是干嘛的？一个生活化类比讲明白

想象一下你网购收快递，包裹外面有一层塑料封条。如果封条完好，说明这包裹没被人拆过；如果封条破了，你就知道中间被人动过手脚。APK 签名干的就是这么一件事——给安卓安装包贴一层"封条"。

这层"封条"用的是一套密钥机制：你手上有一份私钥（只有你知道的那把钥匙），签名时用私钥在 APK 文件上盖个章。安装应用时，安卓系统会拿 APK 里带的公钥（配套的那把锁）去验这个章对不对——对得上说明包没被动过手脚，对不上就拒绝安装。

Apksigner官网介绍的这款工具，在手机上就能完成整套盖章+验章流程。不用装 Java，不用搭 Android SDK，打开应用就能用。

五分钟上手：从下载安装到第一次跑通

第一步：装应用、给权限

安装包从官方下载或者应用商店都能拿到，装好打开，第一个弹窗是要存储权限——必须给，不然它看不到你手机里的 APK 文件也没法把签好的包存回去。如果手滑点了拒绝，去「设置 → 应用 → Apksigner → 权限」里手动把存储改成允许就行。

第二个可能的弹窗是「安装未知应用」，只有当你想用它直接装签好的包时才需要，暂时可以跳过。

第二步：选一个 APK 文件来签

进入「签名」标签页，点那个蓝色的悬浮按钮，选「签名文件」。系统文件选择器弹出来，找到你想签的 APK——随便找一个就行，第一次练手建议用个不大的包，几兆的那种。

第三步：选密钥

第一次用？直接用应用内置的测试密钥就行，不用自己导入。以后有自己的正式密钥库了，再换过来。选完密钥可能要输密码，测试密钥默认密码通常是 123456，不行就看应用内提示。

第四步：勾签名方案

这里新手最容易懵——v1、v2、v3、v4 一堆勾选项。简单记：v1 + v2 都勾上，是目前最稳妥的默认组合。

v2 是 Android 7.0 以后的标配，它对整个 APK 文件做字节级校验，比 v1 的逐个文件检查更安全、更快。v1 留着是为了兼容老设备。v3 和 v4 目前对新手来说用不上，等你需要密钥轮替或增量安装的时候再研究。

第五步：输出

确认信息，点签名。等个几秒钟（小包几乎秒出），签好的包会自动保存在原 APK 同目录，文件名后面加了个 -signed 后缀。

拿这个包去装一下试试——如果原来的包已经装在手机上，先卸掉再装，不然会撞「签名不一致」的报错。

上手后先玩这三个功能

签完第一个包别急着关应用，有三个功能最值得你先摸一摸。

功能一：直接签已安装的应用

刚才的流程是「先有 APK 文件再签」。但很多时候包就在你手机里装着——比如某个应用你想拿它重签一份留档。这时候不用先到处找 APK 文件，回到「签名」标签页点悬浮按钮，选「签名已安装应用」，应用列表直接弹出来，逐行显示包名、版本和体积。找到目标，点一下就直接进入选密钥那一步，后面的流程和签文件完全一样。

你会发现这比导包再签快了不止一个节拍——尤其是系统应用很多的时候，搜索图标一按就能过滤。不过注意：带 Sys 标记的系统应用别乱碰，重签后强行替换可能导致系统启动异常。

功能二：验证签名有没有真的生效

签完包顺手切到「验证」标签页，把刚签好的包拖进去（或者选已安装应用），点验证。你会看到应用告诉你这个 APK 用了哪些方案签的、密钥指纹是什么——把结果和你刚才的密钥对一下，确认无误。这个习惯能帮你排查"为什么装不上"这类问题，很多时候是签名没正确打上去。验证页能看到的签名方案比新手上勾的那几项丰富得多，想深一点的话翻Apksigner文档。

功能三：导出你的密钥库

用测试密钥练手没问题，但正式签名一定要有自己的密钥——而且一定要备份！换手机、应用重装、密钥丢了，之前签的所有包就再也没法用同一个签名更更新了。

在应用里找导出密钥库的入口，设一个强密码，存到网盘里。这步花不了一分钟，但关键时刻能省大麻烦。

小白的三个常见疑问

为什么换了密钥的包装不上？

安卓系统把"同签名"当成"同一家出品"的标志。你用 A 密钥签了 v1，又用 B 密钥签了 v2，系统会认为这是两个完全不同的应用，v2 想覆盖 v1 就会报「签名不一致」。解决方法只有两个：要么先卸旧的再装新的，要么一直用同一把密钥签同一个包。

v1 和 v2 到底有啥区别？

一句话：v1 查每个文件，v2 查整个文件。v1 是早期方案，它逐个解压 APK 里的文件去验签名，速度慢而且有结构漏洞——有人可以在文件没动的情况下改 APK 的 zip 注释字段，v1 就发现不了。v2 把整个 APK 当一个完整的字节流做摘要，任何改动都会让校验失败，速度也快得多。Android 7.0 以上设备原生支持 v2，所以v2 是必勾项，v1 只是兜底兼容老设备用的。

不给存储权限会怎么样？

最直接的表现是点「签名文件」之后看不到任何 APK，或者签名完了包存不回去。权限是 Android 按功能单独管的，Apksigner 需要读写你的文件才能干活。如果手滑点了「拒绝且不再询问」，去系统设置里手动开一下就行。

写在最后

五分钟能跑通，说明 Apksigner 的门槛确实不高——但"能签"和"签得好"之间还有不少细节，比如密钥的生成与保存策略、v1/v2/v3/v4 的组合怎么选、签 AAB 和签普通 APK 有什么不同。这些都可以等你熟练了再慢慢折腾。

先把签名这步的闭环跑通，你就已经跨过了 APK 签名最大的那道坎。进阶方向推荐去看版本线——6.10.0 是 v3/v4 的分水岭，了解一下每版加了什么能力，能帮你判断手上的版本够不够用。
