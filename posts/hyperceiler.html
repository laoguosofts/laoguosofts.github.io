我把 HyperCeiler 嵌进了每周照片整理 + Termux 脚本链，少了至少三次手动介入

2026-10-17 ·约 8 分钟 ·掌柜 老郭

每周要处理照片导出 PDF、切证件照、后台 Termux 不被杀、应用商店不弹窗——以前分散在五六个设置里，现在 HyperCeiler 一条链串起来。

以前我每周要做的事，分散在五六个地方

作为一个每天手机拍几十张的人，每周日晚上我得干这么一串：先把相册里这周攒的图挑出来，PDF 打包发工作群；其中几张要洗出来的，得抠背景换白底当证件照；同时后台挂着 Termux 里跑的 Python 爬虫脚本，出门买个菜回来就被系统杀了，得重新手动拉起来；偶尔打开应用商店装个东西，"今日精选"弹窗先拍脸上，推送通知关了还会偷偷发 banner。

以前我是这么干的：PDF 用 WPS 单独导出一遍；证件照装第三方 App 抠图换底；Termux 每次被杀就手动加白名单，还是防不住；应用商店的推广弹窗没辙，关了通知它还弹。一条下来大概要手动切换五六个 App 或设置页面，中间还经常被 HyperOS 激进的后台策略打断。

后来在 HyperCeiler 上把这条链打通了，现在每周日晚上处理这一套的时间从四十分钟缩到十来分钟。下面讲具体怎么接。

新流程：HyperCeiler 插在四个关键环节

HyperCeiler 是什么简单说一句——给小米 / Redmi 做的 LSPosed 模块，把官方藏起来或限制机型的系统功能解锁，顺便关掉一些默认的烦人行为。去hyperceiler官网能直接拿到安装包，从官方下载渠道就行，装完在 LSPosed 里勾上作用域就行。

第一环：相册 PDF 打包，不再跳 WPS

以前从相册选图导 PDF 要跳 WPS，现在 HyperCeiler 解锁了相册原生的「生成 PDF」。选中一组图后菜单里直接有这个选项，按顺序打包，保存在 相册/PDF 目录。

!相册里直接生成 PDF

这一环省了什么？少了打开 WPS → 新建 PDF → 导入图片 → 调顺序 → 导出 → 回到相册删中间文件，一整套复制粘贴和临时文件清理。

第二环：证件照直接在相册里抠

HyperCeiler 解锁的证件照功能比我用过的第三方 App 靠谱——不用装额外的东西，就在相册里选一张人脸清晰的照片，自动抠背景、换蓝底白底红底、裁剪成一寸两寸小二寸规格。生成的证件照直接保存到相册，或者点微信发送。

这一环没什么悬念，但我之前找过三个第三方证件照 App，要么有水印要么要付费，HyperCeiler 这一套是纯本地处理不出外网，还免了我每次先存到相册再切 App 的往返。

第三环：Termux 后台不被杀——HyperOS 默认的激进策略是真的烦

HyperOS 的后台管理策略在 8GB RAM 以上的机型上完全是负体验。系统默认"应用不活跃超时"就杀，我有时候切出去发个消息，回来 Termux 里跑了半小时的爬虫脚本已经重启了。

HyperCeiler 从 HyperOSXXL 模块合并过来的「禁止自动终止后台应用进程」开关，Hook 的是 ActivityManagerService——它忽略"闲置超时"这条规则，只在内存真不够时才杀。配合「增强最近任务可见性」一起开，所有后台 App 都会显示在最近任务列表里，切回来状态完整保留。

有个细节要注意：这个开关不禁止内存不足时的系统强制清理（Low Memory Killer），也不影响你手动划掉 App——它只挡"超时自动终止"这一类清理。如果你手机 RAM 真的跑满了该杀还是会杀。

另外 HyperOS 还有个"后台弹出界面限制"默认禁止后台 App 弹窗，HyperCeiler 不会改这个设置，如果你开了禁止自动杀后台，记得手动在系统设置里把它关掉——不然 Termux 就算没被杀，弹不出通知窗口也白搭。

第四环：应用商店再也不弹窗不监控

HyperCeiler 给应用商店做了一整套拦截：禁用推广弹窗和 banner、禁止监控你装了什么删了什么、关掉首次启动的"允许推送"弹窗，还有个强制安全评级显示"优秀"的开关——这个有争议，我只在自己非常清楚来源的 App 上用，不会用它绕过陌生应用的安全警示。

最容易断链的两个环节怎么处理

整个流程里我踩过两个坑，单独说一下，其他环节照着hyperceiler文档对照排查就行。

第一个坑是 相册功能的作用域没勾全。HyperCeiler 的相册功能分三个包名作用域——com.miui.gallery（相册本身）、com.miui.creation（小米创作）、com.miui.mediaeditor（相册编辑器，就是点"编辑"后打开的那个独立 App）。只勾相册不勾编辑器，Leica 滤镜和定制画框看不到；只勾编辑器不勾相册，PDF 生成和证件照不出现。三个都勾上，改完重启这三个作用域（或者直接重启手机）。

!LSPosed 里要勾全三个相册相关包名

第二个坑是 系统框架作用域的重启。「禁止自动杀后台」需要在 LSPosed 里勾 system（系统框架）——这是必勾作用域之一。但 system 进程不能单独重启，改完得直接重启设备，这个不能懒。我第一次改完没重启，以为功能不生效，白查了半小时。

效果与边界

说具体数字，以前每周处理这套流程：PDF 导出 10 分钟、证件照 5 分钟、Termux 被杀重拉 3 次每次 2 分钟、关应用商店弹窗和通知 5 分钟，合计约 36 分钟。现在：相册里直接导 PDF 3 分钟、证件照 2 分钟、Termux 一次没被杀过、应用商店弹窗再也没出现，合计约 5 分钟。少了大概 30 分钟，核心是两次手动复制（相册→WPS、相册→证件照 App）和三次手动重拉 Termux 脚本。

这套流程什么时候不划算？三种情况：第一，手机是低端机 6GB RAM 及以下——HyperOS 的后台策略在低端机上有它的道理，强行禁止自动杀后台可能反而导致系统卡；第二，你不跑后台脚本也不常用相册 PDF，那 HyperCeiler 对应用商店的拦截单独装个模块就够了，没必要整套都开；第三，HyperCeiler 2.6.162 起移除了几项依赖云端处理的相册功能（AI 写真、文字烟花、魔法消除、魔法换天、大师滤镜），本地 Hook 确实做不了这些——如果你需要它们，找专门的相册增强模块，别在 HyperCeiler 里死磕。

整体上，把 HyperCeiler 嵌进每周固定的照片 + 后台脚本流程，最大的价值不是解锁了多少功能，而是把本来散在不同 App 和设置里的一串手动操作串成了一条链。以前是我追着每个环节跑，现在是环节在那等我。

这份 HyperCeiler 的功能索引我也挂了三个仓库备份，GitHub 是主仓，Gitee 和 GitCode 做国内镜像，访问不上的时候换一个就行。
