把几千个 DLSite 音声作品收进自家服务器，kikoeru 上手一周记

2026-10-17 ·约 5 分钟 ·掌柜 老郭

从 Docker 部署到标签筛选、跨设备进度同步，折腾一周后聊聊 kikoeru 到底值不值得搭——以及哪些坑我替你踩过了。

为什么我会去装它

说出来有点不好意思——我在 DLSite 上零零散散收了快三年的音声和同人作品，硬盘里堆了好几个文件夹，每次想找一个"上次听到一半的那个耳语 ASMR"，要么翻目录翻到眼瞎，要么干脆忘了放哪了。

某个失眠的凌晨刷到kikoeru官网，描述很诱人：自己搭个小服务器，扫描本地作品库，自动从 DLSite 抓元数据和封面，然后给你一个像流媒体平台那样的 Web 界面——能搜、能按标签筛、能记进度。

我当时想，这不就是我需要的东西吗。

初印象：部署比想象中顺，但也没那么顺

说实话从官方下载拿到安装包、Docker 拉起容器那一下，我以为接下来就是一路顺滑了。docker-compose up -d 一行命令，服务就起来了，打开浏览器进入 Web 界面，那个终端绿配深色的界面看着挺清爽。

但紧接着就遇到第一个坎——扫描。

我把几个大文件夹挂进容器的 volumes 里，点了开始扫描。然后就是等。扫描器一边遍历文件、一边去 DLSite 抓元数据，中途我还在那紧张地盯着日志，怕被反爬封号。结果两个小时后，三千多个作品条目全出来了，大部分还带了封面——说实话我没想到能这么顺利。

不过封面也不是全好的。扫完之后发现有些作品显示占位图，一开始以为是自己挂载路径搞错了，后来翻了kikoeru文档里的排查 FAQ 才搞明白：有的作品在 DLSite 上本来就没上传封面，还有一部分是反爬导致封面下载阶段掉了。解决起来倒也简单，清掉 covers 目录里那几个坏掉的文件（0KB 或者特别小的），重跑一次扫描就补回来了。

标签系统是真的香

真正让我觉得"这东西搭得值"的是标签筛选。

DLSite 本身的分类树就够细了，但 kikoeru 不止抓分类——内容属性、场景标签、视角、声音特征全给你拉下来了。你可以从一个喜欢的作品点进去，顺着它的标签往下挖：比如我从一个"耳语 + 图书馆 + 女性向"的作品出发，一路点标签筛选，居然挖出了二十多个之前完全没注意到的同类作品。

多标签组合取交集这个设计特别实用。想精确到"ASMR 类里带舔耳、场景是雨天、男性向"？一路点下来，结果集越来越小，直到只剩几张你真正想看的卡片。这个比我以前在资源管理器里手动建文件夹分类不知道高明到哪里去了。

进度追踪解决了一个老问题

以前我用本地播放器听音声，一个大合集经常有十几集，听到一半关了播放器，下次打开又得从头翻到上次听到的位置——尤其是合集里文件名还不带序号的时候，简直是噩梦。

kikoeru 的进度追踪是按文件记录的，精确到秒。手机上锁屏的时候自动存一下，电脑上打开 Web 界面直接从那个时间点续播。我甚至在三台设备上试过同一份进度：手机听到 1 分 20 秒锁屏，iPad 打开同一个作品的同一个文件，直接从 1 分 20 秒开播。

这个体验细节让我对它的好感度又上升了一截。

Android 端选哪个，我折腾了三天

kikoeru 没有官方 Android 原生客户端，我一开始用 Chrome 打开服务器地址然后"添加到主屏幕"做了个 Web PWA。能用是能用，但后台播放偶尔会被系统杀掉，也没有真正的离线缓存。

后来听说社区有个叫 KikoFlu 的第三方客户端，装了试试。功能比 PWA 多太多了——悬浮窗控制条、完整的音频下载离线播放、多账户切换（我有两个服务器）、甚至连 UI 配色都能改。缺点是这是第三方项目，分发渠道不是 Play Store，得去作者的发布页手动下 APK。我在可信来源下的，用了一周没遇到什么问题。

适合谁，不适合谁

如果你的硬盘里也堆了一堆 DLSite 音声/同人作品想整理，或者你本来就喜欢折腾点自托管的小服务——搭一个 kikoeru 绝对不亏。Docker 部署半小时搞定，后续基本不用维护，扫描器会自动发现你新加的文件。

但如果你只有几十个作品、或者不想折腾服务器和 Docker 这些东西，那花这个时间就有点不值了——简单建几个文件夹都够用。还有就是它的封面依赖 DLSite 反爬状态，偶尔反爬严格的时候封面下载会掉，需要手动清缓存重扫，这个要有心理准备。

收尾

总体来说，折腾这一周的时间是值得的。以前翻目录找作品的苦日子算是到头了，标签筛选和跨设备进度同步这两个功能，已经足够让它在我的自托管工具箱里占一个常驻位置。

想试试的话，照着前面说的方式拿安装包、拉容器基本不会出大问题。文档写得挺细的，部署、扫描、多端客户端选型都有覆盖。这套资料维护得还算勤快，GitHub、Gitee、GitCode 都能找到最新版。
