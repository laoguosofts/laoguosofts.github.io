auto.js 快问快答：安卓自动化脚本，看完这 8 组问答就够上手

2026-10-17 ·约 7 分钟 ·掌柜 老郭

auto.js 是安卓平台最流行的自动化脚本工具。整理 8 组读者最关心的问题——从它是什么、怎么装、核心 API 怎么用，到后台被杀、打包发布这些进阶话题，一个一个给你讲明白。

整理一篇关于 auto.js 的快问快答，覆盖新手最常问的 8 个问题。

auto.js 到底是什么？

一句话：auto.js 是一个让安卓手机「自动帮你干活」的脚本工具，它的官网上有完整功能列表和截图。你写一段 JavaScript 代码，它就能模拟人的手指去点屏幕、滑界面、读文字、判断状态——签到、抢单、批量操作 APP，全靠脚本驱动，不用人盯着。

它的核心跑在 Rhino JS 引擎上，不是 Node.js 那一套。ES5 语法全支持，ES6 支持 let、const、箭头函数、模板字符串，但 async/await、Promise、class 继承这些现代特性在原版里用不了。Pro 9.x 之后追加了 Node.js 引擎，完整支持 ES2021，但那是付费版的事。

谁需要用 auto.js？

有重复操作痛点的人。比如每天要在十几个 APP 上签到领积分的用户，抢火车票要反复刷新余票的旅客，批量上传内容到电商后台的运营同学——只要是「同一套动作每天都做、做起来机械枯燥」的场景，auto.js 都能顶上去。

它不替代 APP，不破解什么，就是个「按你写的指令去点屏幕」的工具。写得好的脚本可以完全脱离主界面工作，挂在后台自己跑。

装起来麻烦吗？核心要开什么权限？

装 APP 本身不麻烦，应用商店或官方下载拿 APK 安装就行。真正绕不过去的是两个必开权限：无障碍服务 + 悬浮窗。

无障碍服务 auto.js 需要它才能读取屏幕上的控件树——知道当前界面有哪些按钮、哪些文字、哪个位置可以点。不开的话脚本里的 text("签到").click() 根本找不到目标。悬浮窗是脚本运行状态的可视化入口，那个常驻屏幕边缘的圆形小浮球就是它。没开悬浮窗也能跑脚本，但你没法随时暂停、继续、停止，也没法一键打开布局分析器调试界面。

部分国产 ROM 对这两个权限有坑。比如 MIUI 10 以上，普通悬浮窗和全屏悬浮窗是两个独立开关，得分别开。vivo、OPPO 的早期版本即使开了前台服务也可能杀后台，这个后面会说。

脚本怎么写？需要很懂 JavaScript 吗？

不用全懂，会基础就能上手。auto.js 的核心 API 是它自家的——text()、id()、className() 定位控件，.click()、.waitFor()、.findOne() 操作控件，sleep() 延时，toast() 弹出提示。这些才是写脚本的主体。

Rhino JS 引擎虽然老，但日常用的变量、函数、数组、对象、条件判断、循环全齐：

// 定位"签到"按钮并点击
text("签到").waitFor().click();

// 循环点 10 次
for (var i = 0; i < 10; i++) {
  text("下一个").click();
  sleep(1000);
}

Rhino 有几个老版本特有的坑要留意：typeof null === "object" 是 JS 历史遗留、早期版本没有 const、不支持 ESM 模块语法只能用 require()。但简单脚本逻辑不会踩到这些。复杂场景可以去auto.js文档查详细说明。

脚本跑到一半被系统杀掉怎么办？

Android 为了省电，对后台进程的清理越来越激进。auto.js 如果在后台被系统回收，正在跑的脚本会悄无声息地停掉——没有报错、没有崩溃提示。

目前最有效的手段是开前台服务。开了之后通知栏会出现一个常驻的「进行中」通知，告诉系统「这个应用正在做重要的事，别杀我」。

但前台服务不是 100% 保险。系统极端缺资源时（同时开了很多重型应用）前台服务也可能被回收。想要最大存活率，建议三重保障：前台服务 + 电池优化白名单 + 自启动管理。另外部分国产 ROM（vivo/OPPO 早期版本）即使开了前台服务也可能杀，这种情况就得看各品牌的自启动管理里能不能把 auto.js 加到白名单。

能打包装成自己的 APK 吗？

Pro 版可以，而且配置很简单。打包项目里有一个 config.json 文件，几个核心字段必填：应用名 name、包名 packageName（Java 风格如 com.example.signin）、版本号 versionCode 和版本名 versionName、入口脚本 main。权限字段按需要声明——ACCESSIBILITY 和 SYSTEM_ALERT_WINDOW 是必开的两个，其他像存储、网络、相机按需加。

Pro 版还有三个好用的配置项：encrypt 加密脚本源码、buildNodeModule 打包时把 npm 模块（如 axios、cheerio）构建进去、minify 打包前压缩代码。配置好之后一键打包就出 APK，装到手机上脚本直接跑，不用再开 auto.js 主应用。

有哪些常见的坑？

最频繁遇到的有三个：权限分级、引擎差异、后台被杀。

权限坑前面提过，MIUI 悬浮窗分普通和全屏两档，都要开。引擎差异是 Rhino 的老问题——如果你之前写前端或 Node 写惯了，async/await、Promise 这些语法在原版 auto.js 里用不了，得老老实实写回调或者同步循环。后台被杀是 Android 全局的事，三重保障能大幅降低概率但不能完全杜绝，长时脚本建议加一个定期自检：如果检测到自己不在运行就自动重启。

还有一个小坑：部分全屏沉浸式应用（视频播放器、游戏）会自动隐藏悬浮窗，这是正常的系统行为，回到普通界面就恢复了，不是故障。

值不值得长期用？

值得，前提是你确实有重复操作的痛点需要解决。auto.js 上手门槛不高，核心 API 就那几十个，官方提供了详细的参考。但要写好脚本、处理各种边界情况（网络卡、界面变了、权限被关了），还是需要持续练习和调试。它不会替你解决问题，但能替你省时间——省下来的时间去做更值得的事。

这套资料在 GitHub、Gitee、GitCode 三个仓库都能拿到，选一个访问顺畅的就行。
