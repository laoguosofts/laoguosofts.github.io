用了吉里吉里2 三年才发现的五个隐藏技能

2026-10-17 ·约 8 分钟 ·掌柜 老郭

大多数人拿 krkr2 只会写剧情脚本，但它还藏着图层自定义、变量互通、引擎自检等不少私货，翻完文档才惊觉之前一直在用它的最表层。

你以为吉里吉里2 就是个写 Galgame 剧情的剧本工具？它的官网明着就是主打剧本工具定位的，把 scenario 文件一行行填对话、加几个 [bg] [chara] 标签就能跑——我最开始也是这么想的。直到某天翻到从下载拿到的 SDK 里自带的 TJS2 源码和图层系统文档，才拍大腿：合着之前三年一直在用它的最表层，底下还藏着一堆官方几乎不宣传、但用起来能省好几百行脚本的玩意儿。

今天就把这些我挖出来的私货端出来，五个隐藏技能，从"在哪找"到"怎么开"讲清楚。

一、图层编号不是摆设——自定义图层玩出花

新手时期的认知里，图层就是：Layer 0 放背景、Layer 1~3 放立绘、UI 和文字层自动搞定。直到我发现通用的 image 标签可以在任意编号创建新图层，而且编号越大越靠上——这个规则一开，画面层级瞬间自由了。

藏得真深，连 KAG 标签速查里都没重点提。用法超简单：

[image storage="img/flower.tlg" layer=10 x=500 y=300 time=300]

这里的 layer=10 是你自己随便编的号，只要不和已用的冲突。我现在用它做什么？给对话框加装饰边框（layer 9 压在 UI 层上面）、做天气粒子叠加层（layer 5）、甚至在过场动画里插一张过渡插画。关键是还能直接操作图层对象做动画：

[tjs]
Layer.get(10).moveTo(200, 400, 800);

立绘从左滑入那一下，就是这么来的——用 TJS2 的 Layer.get() 拿到图层实例，调 moveTo 做平滑移动。官方文档里提过一句"图层有编号"，但没说编号可以乱编，更没说 TJS2 能直接改图层属性。这就是传说中的"看了等于没看"。

什么人用得上：想做复杂画面效果的开发者；什么人可以无视：只会写纯剧情对话的同学可以先跳过。

二、KAG 变量和 TJS2 全局变量是双向互通的

这个我最开始完全没意识到，直到在文档里看到一句不起眼的注脚。

吉里吉里2 有两套东西：KAG 标签写在 scenario 里，TJS2 是底层脚本。我之前以为它们各管各的，KAG 用 [set variable="xxx"] 存变量，TJS2 在独立 .tjs 文件里写类——两套变量系统互不相干。

但真相是：只要是全局变量，两边直接互读互写，连导入都不用。

; KAG 里先设一个全局变量
[set variable="playerName" value="阿良良木"]

; 嵌在 scenario 里的 TJS2 代码块直接用
[tjs]
Layer.current.message = "欢迎你，" + playerName;

反过来也一样——TJS2 里 global coin = 100;，KAG 那边 [eval exp="coin"] 就能把值打出来。

这个互通功能藏得极其恶劣，因为文档里分章节讲 KAG 和 TJS2，互通只在一个"进阶提示"的角落里提了一下。但它的价值是：你可以用 TJS2 做复杂的数值计算、数组操作，算完把结果塞回 KAG 变量继续跑剧情——不用在 KAG 里硬写循环，KAG 根本没真正的循环标签。

什么人用得上：需要做数值、状态管理的游戏逻辑；什么人可以无视：纯视觉小说类项目确实用不上，但谁没个做小游戏的时候呢？

三、[system] 标签——引擎状态的隐藏查询口

我一直以为 KAG 标签就是些控制画面、音频、流程的玩意儿，直到某次为了兼容性问题翻到了 [system] 标签。这个标签是个万能查询器，能拿到引擎的实时状态：版本号、窗口尺寸、当前场景、存档路径……

最实用的场景是做兼容性判断：

[tjs]
var version = System.version;
if (version < 230) {
    Layer.current.message = "本项目需要 krkr2.30 以上版本";
}

还有 System.windowWidth / System.windowHeight，用来做响应式布局。官方文档里提了一句 [system] 可以"查询引擎状态"，但没说有哪些可查的属性——要翻 KAG 的 TJS2 源码才能列全。这大概就是"隐藏功能"的定义：能用，但文档几乎等于没写。

四、动画效果的组合技——闪黑切换场景

场景切换，新手的做法是：先淡入淡出背景。老玩家会用一个经典组合：闪黑 + 换背景 + 闪回来。

[effect flash color=black time=500]
[bg storage="bg/new_scene.tlg" time=0]
[effect flash color=black time=500 reverse=true]

第一行闪黑 500ms，第二行在黑屏瞬间无缝切背景（time=0 没有过渡），第三行从黑里淡回来（reverse=true 是反方向淡出）。这个操作文档里作为"闪黑闪白"的示例一笔带过，但没人说这就是行业标准的场景切换套路——我是在扒别人源码的时候才学会的。

加上 [effect shake time=500 intensity=5] 做震屏、[effect flash color=white time=200] 做受击闪白——这几个 effect 标签的组合，能顶得上好几百帧手绘动画。

五、控制器模式——实时执行 TJS2 语句的调试利器

最后说一个调试向的隐藏入口。SDK 里有个开发调试界面 DLL 叫 krdevui.dll，它的功能远不止报错弹窗——启动时选择打开"控制器"，就能在运行时实时执行 TJS2 语句。

你可以边跑项目边改变量、调图层属性、测试表达式，不用每次改完脚本重新加载。对于数值平衡的调参阶段，这个功能能省掉"改文件→重启→找位置→看效果"的无限循环。

但注意一个坑：分发你的项目给玩家时，别把 krdevui.dll 带上——带上了等于给了玩家一个能在运行时随便改东西的后门。SDK 自带的 Releaser 打包工具会自动处理这个，但手动拷贝的时候别漏。

哪个坑别踩

说几个我踩过的，省得你重蹈覆辙。

第一，同时活跃图层别超过 15 个。样本里提了一句"可能影响低端机性能"，我实际测下来——12 个以上在老安卓机器上就开始掉帧。图层多的时候定期 image clear 清不用的，别图省事一股脑堆上去。

第二，大图要预加载。超过 1920x1080 的背景图，每次切换都是卡顿。解决办法是在 startup.tjs 里提前 Image.load("bg/school.tlg", true)，第二个 true 是预加载到内存。

第三，别用中文路径。这个在安装说明里写了，但值得再提一次——某些老插件的路径解析硬编码了 ASCII，中文路径会静默失败，报错信息还是"找不到文件"，排查起来浪费生命。

收尾

吉里吉里2 这类老牌引擎的魅力就在这里了——二十年的迭代，底层藏着一堆好用到飞起、但没人整理成中文文档的东西。它的"表层"是剧本工具，"里层"是一套完整的游戏框架。把图层、TJS2、控制器这些东西用透，其实就是在用它最核心的设计。

这套资料我分别同步到了GitHub、Gitee、GitCode 三个仓库，国内访问走 Gitee/GitCode 更顺畅，主仓库有什么问题也不怕断档。
