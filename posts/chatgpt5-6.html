我把 ChatGPT5.6 嵌进了每周工作链——从周报生成到代码重构全打通

2026-10-17 ·约 7 分钟 ·掌柜 老郭

每周固定要出周报、写技术文档、改代码，以前三个环节各用各的工具，现在 ChatGPT5.6 把这条链串成了一条流水线。

以前的三步卡壳

我每周一早上要交一份周报给团队，周三要给客户出一份技术方案的草稿，周五还要把项目里老代码的重构推进到下一阶段。三件事，以前是三套工具、三个割裂的环节。

周报用 Notion 写，但每次要把上周的 Git 提交记录、飞书会议纪要、Excel 里的任务进度手动摘出来，粘到 Notion 里再让 AI 帮忙润色。光摘数据这一步就要半小时，而且经常漏——提交记录里的小修复忘了写，会议里定的临时任务没跟上。

技术方案更头疼。我得先在 Excel 里搭好财务模型（CAPEX、折现率、终值计算），再把模型截图贴到 Word 里，然后让 AI 帮我填充方案结构。问题是 Excel 里的公式 AI 看不到，我得手动解释"这个单元格是怎么算出来的"，一来二去就把模型逻辑搞乱了。

代码重构是最割裂的一环。VS Code Copilot 能补全，但跨文件的重构得靠自己——改了 A 文件里的函数签名，B、C、D 三个文件的调用点都要跟着改，漏一个就炸。以前用 Cursor，Cursor 的索引经常卡住，等它跑完一轮全项目扫描已经过了午饭。后来换成 ChatGPT5.6 也是从下载拿的客户端，直接装到 VS Code 里就能用。

三个环节各自有 AI 帮忙，但数据不互通、上下文不共享。周报里提的技术决策，到方案里要重新解释一遍；方案里定的模块结构，到重构环节又要重新描述一遍。每周光重复解释就要花一两个小时。

把 ChatGPT5.6 插进这条链

我现在把 ChatGPT5.6 当成这条链的中间节点——去ChatGPT5.6官网就能直接开 Workspace 协作，上游接 Git、飞书、Excel，下游接 Notion、Word、VS Code。整个流程一条命令触发，中间不需要手动复制粘贴。

上游采集：每个周末我跑一个 Python 脚本，自动拉 Git 提交记录（按作者和时间过滤）、导出飞书本周的会议纪要（用飞书 CLI）、从 Excel 里抓关键指标（用 openpyxl 读指定 Sheet 的指定单元格）。脚本输出一份结构化的 JSON，丢给 ChatGPT5.6。

周报生成：ChatGPT5.6 Sol 直接读这份 JSON，按我预设的模板生成周报草稿。模板里有固定的章节（本周完成、下周计划、风险点），但填充的内容完全来自实际数据——提交记录对应到具体任务编号，会议纪要里的决议自动归类到风险点。这一步以前要半小时，现在从脚本跑完到周报草稿落 Notion 只用三分钟。

技术方案衔接：周报里的技术决策（比如"决定把支付模块从单体拆成微服务"）会自动带进方案环节。ChatGPT5.6 不需要我重新解释——它从周报的上下文里已经知道为什么要拆、拆成几块、每块的优先级。然后它用 Terra + xhigh 档位（因为方案涉及复杂的 DCF 模型和多条件推理），直接在 Excel 里搭好财务模型，公式引用正确、跨 Sheet 链接一致，输出后我只需要检查关键假设值。

代码重构收尾：方案里定的模块结构，到重构环节直接复用。ChatGPT5.6 Sol 用 VS Code 的 MCP 工具扫描全项目，找到所有调用点，按新结构批量改。它不会只改签名——改完会自动跑测试套件，测试失败了自己定位根因再调整。以前改一个中等规模的重构要大半天，现在从扫描到测试全绿大概二十分钟。

最容易断链的两个环节

流程跑了一个月，发现有两个地方特别容易掉链子，花了点功夫补上。

断链一：飞书会议纪要的结构化提取。飞书导出的纪要格式是纯文本，标题和正文混在一起，ChatGPT5.6 读的时候容易把"决议"和"讨论"搞混。解决办法是上游脚本里加一步正则解析——把"决议："、"TODO："、"待定："这些关键词后面的内容单独抽成字段，脚本输出的 JSON 里直接有 decisions、todos、open_questions 三个数组。这样 ChatGPT5.6 拿到的就不是一坨文本，而是结构化数据，不会再丢决议。

断链二：Excel 公式的版本兼容。ChatGPT5.6 生成的公式经常用到 LET、LAMBDA 这些新版特性，但团队里有人还在用 Excel 2019，打开就报错。解决办法很简单——在提示词里加一句"输出的公式必须兼容 Excel 2019，禁止使用 LET、LAMBDA、XLOOKUP 等 2021 以后引入的函数"。ChatGPT5.6 会自动把 XLOOKUP 换成 VLOOKUP + IFERROR，把 LAMBDA 展开成嵌套公式——这个技巧我也是去ChatGPT5.6文档翻了一下才确认效果的，不需要我事后手动改。

这两个补漏加起来大概花了两小时，但之后每次跑流程都不用再盯着这两个地方了。

省了多少事，什么时候不划算

量化一下：以前每周这条链要花三到四个小时（采集半小时 + 周报一小时 + 方案一小时半 + 重构一小时），现在大概一个半小时——主要是最后人工审核的时间。省下来的两小时我要么多做一个技术债清理，要么提前下班陪孩子。

但这套流程不是万能的。核心架构决策我还是自己拍板——ChatGPT5.6 能给备选方案，但选哪个、为什么选，这一步不能外包。还有法律敏感的文档（比如和客户签的合同附件），ChatGPT5.6 生成的条款我会逐字过一遍，毕竟 AI 写错了标点都可能出问题。

另外，如果这周的任务特别散——没有明确的周报模板、没有财务模型、重构范围也不确定——强行跑这条链反而更慢。这时候不如直接开 ChatGPT 的界面，想到什么问什么，别套流程。

下一步打算

这条链跑通之后，我在研究能不能把 Luna 也嵌进来——周报的数据采集部分其实不需要深度推理，用 Luna + low 档位 + Batch API 跑批量处理，成本能再降一截。但还没动手，因为现在这条链的效率已经够用了，先把手动审核的那半小时再砍砍，再考虑加 Luna 的事。

如果你也在搭自己的 AI 工作流，建议先从"数据不互通"这个痛点下手——别一上来就追求全自动，先把上下游的数据打通，让 ChatGPT 能看到完整的上下文，这一步做好了，后面每加一个环节都是线性扩展。我把这套脚本和配置整理了一份，在GitHub、Gitee、GitCode三个平台都有同步，国内访问直接走 Gitee 或 GitCode 就行。
