Operit AI 装了大半年，说说那些当初没在意的事

2026-10-17 ·约 8 分钟 ·掌柜 老郭

从 v1.6 用到 v1.9，从只跑本地 MNN 到用它远程控电脑，长期使用里哪些习惯固化了、哪些功能沦为摆设、哪些判断被推翻了。

当初装 Operit AI官网 纯粹是好奇——手机上跑本地大模型这事，听起来就够折腾也够诱人。装的时候版本号还是 v1.6，MNN 引擎刚内置不久，主打骁龙旗舰上能跑小模型到十几 tok/s。我抱着试试看的心态，安装包从下载拿的，下了个 TinyLlama-1.1B 塞进 models/ 目录，就把它扔一边了。

这一扔就是好几个月。中间断断续续升到 v1.7、v1.8，直到现在 v1.9 出了 Windows 远程控制，我才重新捡起来。这半年多的时间里，对这个应用的感受从"又一个花架子"慢慢变成了"每天都想点开看看"——当然也伴随着几个当初没料到的糟心细节。

越用越顺手的：MNN + Qwen2.5-1.5B 这条路线

刚装的时候我同时试了 MNN 和 llama.cpp，直觉上觉得 GGUF 生态丰富、模型多，应该是后者更靠谱。结果用了一段时间发现自己完全错了。

llama.cpp 虽然格式通用，但在手机上跑 Qwen2.5-7B-Q4 那个速度实在忍不了——六七 tok/s 跟挤牙膏似的，等它回复完我都忘了刚才问了什么。后来切换到 MNN + Qwen2.5-1.5B，速度直接跳到十二到十六 tok/s，感觉完全不一样了。最开始那几天我还纠结"模型小了会不会智商不够用"，但日常对话、简单代码生成、帮我写个脚本摘要这些场景，1.5B 其实够用。

现在的固定流程是：手机端 MNN 处理日常，需要复杂推理的时候再手动切到 llama.cpp 跑大一点的模型。切模型的操作我练熟了，从打开设置到切换引擎加选模型，大概三十秒搞定——也算被打磨出来的肌肉记忆。

有个细节值得提一下：Operit 支持同时配置多个本地模型，我现在 MNN 和 llama.cpp 各挂了两个，按需切换。当初刚装的时候以为"引擎二选一"，后来去Operit AI文档翻了一下才知道其实可以并存。

越用越烦的：发热和降频

这是我当初完全没预料到的问题。MNN 虽然速度快，但手机连着跑个十几分钟，后盖就开始发烫。我那台骁龙 8 Gen 2 玩游戏都没这么热过。

发热直接导致降频。有几次我让它连续生成一段长代码，跑了大概五分钟，速度从十几 tok/s 掉到五六，等手机凉下来又能回去。最烦的是有时候急着要结果，就眼睁睁看着它越跑越慢。

我试过几个办法：关后台、开发者选项里关掉强制 GPU 特性（比如 4x MSAA）、充电时不跑大模型。都有一些效果，但没有根治——推理本身就是吃 CPU/GPU 的活，手机这种被动散热的东西，上限摆在那。

后来也慢慢接受了：让它跑十分钟，停一会儿让手机缓一缓，再继续。把它当一个需要"中场休息"的伙计，反而没那么急了。

每天离不开的：让手机反过来指挥电脑

Operit v1.9 加的 Windows 终端远程控制，是这半年里对我改变最大的功能。

通路方向跟一般远程桌面反过来——不是电脑远程控制手机，而是手机通过 SSH 连到 Windows，在 PowerShell 里执行命令。刚看到这个功能的时候我觉得挺鸡肋："我坐在电脑前为什么还要用手机控制它？" 但真用起来之后发现场景比想象中多得多。

最常用的一个场景：手机上用 GPT-4o 写代码，写完直接让 Operit 推到电脑上跑 Python。手机负责 AI 推理和交互，电脑负责重型计算，两边各司其职。还有半夜躺在床上的时候，想起电脑上有个构建任务没跑完，翻个身掏出手机让 Operit 远程跑 npm run build——不用爬起来。

配置其实不难：Windows 10 自带 OpenSSH Server，装上后 Operit 里填个内网 IP 加账户就能连。但我犯过一个低级错误：最开始用密码登录，后来才知道 SSH 密码容易被嗅探，换成了 SSH Key 免密。还有个坑是 Windows 上 SSH 启动慢，第一次连接经常要等个好几秒，习惯就好。

安全上我还是比较保守：只用普通账户（不是管理员），Hook Runner 危险命令拦截一直开着，公网从来没开过 SSH。

当初完全没碰的：OCR 视觉理解

这个功能 v1.7 就加了，内置 AutoGLM 视觉模型。但我一直觉得"手机拍照然后 OCR"这件事太老套了——市面上各种 OCR 应用遍地都是，Operit 能比专业的好到哪去？

直到上个月老婆让我帮忙整理一堆纸质发票，拍了几十张照片要转成电子表格。我本来打算装个专门的 OCR 应用，想起来 Operit 有这功能就先试了一张。

结果出乎我意料。清晰的发票识别精度很高，日期金额商品明细基本都对，还能自动整理成结构化表格。手写的部分精度差点（大概七八成），但也够用了。最方便的是整个流程都在 Operit 里完成：拍照 → 直接在对话里说"帮我把这张票据的日期、金额、收款方识别出来" → 它处理完直接给我 Markdown 表格，不用导出导入。

后来才知道 AutoGLM 主要服务于 UI 自动化，但单独用来做 OCR 也能打。我现在偶尔用它把手写笔记转录成 Markdown，虽然手写字识别率不算顶尖，但胜在流程连贯，不用在多个应用之间切换。

当初高估了什么，低估了什么

半年用下来有几个判断被推翻了。

高估了大模型的"智商"，低估了小模型的"够用"。 最开始我执着于在手机上跑七八 B 的模型，觉得小模型太玩具。但日常场景里，1.5B 的 MNN 模型已经能覆盖大部分需求——真正需要大模型的时候其实不多。手机上最宝贵的不是"能不能跑"，而是"能不能流畅跑"。

低估了"离线可用"这件事的价值。 刚开始我主要用云端大模型（GPT-4o、Gemini），本地模型只是偶尔玩一下。后来出差在高铁上没网，突然发现 Operit 的本地模型在这种场景下就是救命稻草——帮我改文档、写脚本、翻译，全离线。那次之后我才意识到，在这个"随时联网"被当成理所当然的时代，有个本地能跑的备选，心里踏实很多。

高估了 OCR 的必要性，低估了远程控制的便利。 这俩刚好反过来。OCR 我以为会经常用，结果除了整理发票那一次，碰得很少。远程控制当初觉得是噱头，现在几乎每天都在摸——要么手机写电脑跑，要么手机远程查个电脑上的东西，变成了最自然的工作流延伸。

会不会卸载？

目前完全没打算。MNN 引擎让它在手机上跑出了像样的速度，远程控制又打通了手机和桌面的协作链路，这两个功能叠在一起，让它在我手机上占了一个其他应用替代不了的位置。

如果哪天它让我换了新手机但 MNN 没适配新芯片架构、或者远程控制被砍掉了，这两个任何一个信号出现，我都会认真考虑换别的。但现在来看，Operit 还在稳步迭代（从 v1.6 到 v1.9 才半年），短期内看不到这种可能。

说个反直觉的感受：当初装的时候想着"研究一下就删"，没想到留下来的不是那些一开始让我兴奋的本地大模型性能参数，而是一些慢慢养成的小动作——随手拍个图让它转 Markdown，躺在床上让电脑跑个构建任务，出门在外手机上改代码推到电脑上执行。这些小动作单独拿出来都不是什么革命性的体验，但凑在一起，就成了一个离不开的东西。
