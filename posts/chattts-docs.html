ChatTTS 踩过的五个坑——从显存爆掉到音色丢失，全记录

2026-10-17 ·约 7 分钟 ·掌柜 老郭

ChatTTS 上手很快，跑起来也简单，但真要稳定用起来，几个藏在背后的坑会让你怀疑人生。这篇是我踩完之后攒的避坑笔记。

第一次从ChatTTS官网拿到安装包，官方下载页直接有现成的打包版本，装完依赖、加载模型、敲一行 chat.infer("你好，世界")，音箱里就出来声音了。当时觉得这东西也太省心了吧。

然后我就开始用它做正事：批量合成一批角色台词、给短视频配音、把自己写的文章读成语音……坑就是在这个时候一个个冒出来的。有的是半夜跑脚本突然炸显存，有的是保存好的音色第二天起来变了调，还有一次朋友问我能不能帮他克隆个明星声音，我张口就说能，翻了半小时ChatTTS文档才发现根本不行。

ChatTTS 看着简单，其实有几个地方容易翻船。下面按我踩坑的时间顺序说。

坑一：跑着跑着 GPU 突然炸了

症状：脚本跑了半小时，中间突然抛异常——RuntimeError: CUDA out of memory. Tried to allocate ...。第一次遇到时我以为要重装 CUDA，甚至还重新装了一遍显卡驱动，问题没解决。

原因：ChatTTS 的模型权重本身不大（FP32 下约 1.2 GB），但中间缓存会随着生成长度和批量数线性增长。我当时把二十多段台词一次性扔给 chat.infer()，批量推理确实快，但显存占用直接翻倍了。而且当时浏览器还开着几个视频页，后台还有个训练脚本没关，几处加起来就爆了。

解法：最直接的是把批量大小从 10 降到 1 或 2。批量推理不一定总比逐条快——除非你一次性处理几十段以上，不然逐条跑更稳。另外长文本建议拆成 200~300 字的片段逐段合成，显存占用会小很多。

清理显存的话，torch.cuda.empty_cache() 能释放 PyTorch 占的缓存，但浏览器、IDE、其他 Python 进程占的显存它管不着。真遇到显存紧张，重启 Python 进程比 empty_cache() 更彻底——这个经验记一下。

实在跑不动就 CPU 降级：chat.load(compile=False, device='cpu')，速度慢 5~10 倍，但一定能跑通。我在没有显卡的笔记本上就是这么干的，虽然慢，但功能完整。

坑二：保存好的音色第二天起来变了调

症状：前一天我在调一个角色的音色，采样了十来个，终于挑到一个满意的，存成了 JSON 文件。第二天跑脚本加载这个文件，出来的声音跟昨天完全不一样——不是完全变了个人，是音色特征对不上，听起来像两个说话人。

原因：说话人嵌入字符串是序列化的 JSON，本身没问题，但 ChatTTS 升级到新版本后，嵌入格式可能有差异。我前一天还是 0.2.2，第二天顺手 pip install -U ChatTTS 升到了 0.2.3，嵌入格式变了旧字符串就不兼容了。

解法：两个办法。一是别随便升级——如果手上有正在用的音色，先把版本锁死（pip install ChatTTS==0.2.2），确认新版本兼容再更。二是如果真不兼容了，重新采样即可，损失也不大，反正几百字节的字符串存起来没成本。

顺便说一句，说话人嵌入跨设备是可以复用的——我在台式机上采样保存的 JSON，拷到笔记本上加载没问题，不同 GPU、不同操作系统都行。嵌入本身就是一个确定的向量，跟在哪个进程里采样的没关系。

坑三：以为能克隆声音，结果不行

症状：一个朋友想让 ChatTTS 克隆某个电台主播的声音，他说听说 ChatTTS 支持"多说话人"。我没仔细想就说应该可以。然后他拿了主播的一段录音来，发现根本没地方把音频文件喂给模型。

原因：ChatTTS 的"多说话人"是从训练集中采样——sample_random_speaker() 返回的都是模型在训练时见过的说话人，不是让你上传一段录音来克隆。这个设计决定写在文档里，但太容易被忽略。

解法：如果需要声音克隆，得换其他项目——OpenVoice、so-vits-svc 都是专门干这个的。ChatTTS 定位是通用 TTS，不是克隆工具，别混为一谈。

坑四：批量推理反而更慢

症状：我写了个批量处理脚本，把 50 段台词一次性扔给 chat.infer()，以为效率翻倍，结果总耗时比逐条跑还长。

原因：批量推理的优势在于共享模型加载开销——但模型加载只占整个流程不到 5%的时间，主要耗时是生成本身。批量越大，中间缓存越多，显存压力越大，反而可能触发显存分页，速度骤降。我之前一次处理 20 段时就遇到了这个情况，显存不够导致 GPU 在做内存交换。

解法：批量大小控制在 5 以内比较合适。如果是长文本分段处理，逐段跑就好，没必要强行批量。

坑五：合成出来带杂音，以为是模型坏了

症状：第一次用的时候，合成出来的语音背景有沙沙的杂音，我以为下到了坏模型，重新下了两遍权重文件。

原因：官方有意在开源的 4 万小时模型里加了轻微背景杂音，用来做反滥用设计——防止有人拿开源模型做违法事情。10 万小时的主模型杂音更少但没有公开权重。所以你听到杂音不是模型坏了，是官方故意这样做的。

解法：如果杂音能接受就忍忍。实在在意的话，要么等主模型开源，要么后期用降噪工具处理一下。

防坑清单

写完了五个坑，列个速查表，下次开工前扫一眼：

  • 显存紧张？先减批量大小和文本长度，实在不行 CPU 降级
  • 升级前先锁版本，手上有在用的音色别乱更
  • 批量推理控在 5 条以内，不是越多越快
  • 杂音是官方故意的，不是模型坏了
  • 需要声音克隆请换工具，ChatTTS 不做这个

知道这些坑之后，这软件其实相当省心。
